title: "Threat model"
description: "What Knot defends against, and what it deliberately does not."
---

## The target

**Liquidity providers in fragmented pairs.** When one pool for a pair runs shallow or stale, it
can quote beyond what the pair's combined liquidity supports. An arbitrageur takes that quote.
The value was funded by that pool's LPs.

## Explicitly not the target

**Sandwich attacks.** They hurt the swapper, not the LP. LPs earn fees on both legs and the price
round-trips. Measured across real Base flow, sandwich attacker legs carry roughly **10× less**
toxicity to LPs than average flow. Scoping honestly here is a design decision, not an omission.

## Attack surface

| Vector | Status |
| --- | --- |
| Cross-pool round trip | **Closed.** Flips from +13.58 to −0.075 on a 5-token stake |
| Trade splitting | **No advantage.** Sliced output is marginally worse than one large trade |
| Sandwich through one pool | **Unprofitable.** Attacker ends 1.484 token0 down |
| JIT liquidity | **Blocked.** Fresh deposits cannot back a same-block quote |
| Multi-block extraction | **Bound holds.** Quotes tighten as the pool drains, never loosen |
| Reserve manipulation | **Fuzzed**, 1,000 runs, no underflow, aggregate never drifts |
| Coalition of members | **Partially open**, see [Limits](/security/limits) |

## Permissions

Knot enables `beforeSwapReturnDelta`, which Uniswap's own
[v4 security guidance](https://github.com/Uniswap/uniswap-ai) rates **CRITICAL**. This is
unavoidable for a custom curve: the hook replaces the pricing function, which is the flag's
intended legitimate use. It means the hook is in the highest-scrutiny tier and should be read
accordingly.

| Control | Implementation |
| --- | --- |
| Reserve mutation | Restricted to registered members |
| Membership | Owner-gated, bounded member cap |
| Reentrancy | `nonReentrant` on federation state changes; no callbacks during a quote |
| Rounding | Both directions round against the taker |
